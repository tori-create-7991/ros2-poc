# 認証ハンドシェイクの観測（資格情報のない参加者は、相手の証明書を引き出せるか）

SROS2 を有効にした環境（環境 C）で、資格情報のない参加者、または不正な資格情報を提示する参加者が加わろうとしたとき、
認証済みの相手が自分の証明書を含むハンドシェイクを**平文で**送ってくるかを、tcpdump で観測した。

- 手順: `bash scripts/sros2/handshake-probe.sh`（事前に `scripts/up-env.sh c` と診断コンテナの起動が必要）
- 観測点: ros2lab-a のネットワーク名前空間（サイドカーで tcpdump）。ros2lab-a の参加者（認証済み）が publish している間に、相手を加わらせる
- 数える対象: pcap に `BEGIN CERTIFICATE` が出た回数、ros2lab-a の証明書に固有の行（公開鍵の一部）が出た回数、subject 名（`ros2lab_a`）が出た回数
- 強度: 「参加者として加わる」まで。相手に不正な操作はしていない
- 実測日・バージョン: 2026-10-05、Fast DDS 2.14.6 / sros2 0.13.6

## 結果

| 相手の種類 | ros2lab-a の証明書が平文で出た回数 | 補足 |
|---|---|---|
| 認証済みの ros2lab-b だけ（基準） | 2 | 認証済み同士のハンドシェイク。これだけでも証明書は平文で見える |
| 鍵なし（セキュリティなし）の参加者 | 2（基準と同じ） | 追加のハンドシェイクは起きない。鍵なしの参加者は無視される |
| 自己署名の証明書を提示する参加者（2 回） | 19 / 19 | 基準を大きく上回る。ros2lab-a が自分の証明書を含む要求を繰り返し送ってくる |
| 想定外の CA が署名した証明書を提示する参加者（2 回） | 19 / 19 | 同上 |

## 分かったこと

- **資格情報をまったく持たない参加者は、相手の証明書を引き出せない。** 認証済みの相手は鍵なしの参加者に対してハンドシェイクを始めない。
- **自己署名や別 CA の証明書でも、「それらしい資格情報」を提示すれば、相手に自分の証明書を送らせられる。** 相手は提示された証明書を検証する前に、自分の証明書を平文で送っている。
  参加自体は拒否される（通信は成立しない）が、証明書の内容（subject、公開鍵、有効期間、発行者）は見える。
- したがって、**受動的な観測だけでは、参加者が起動しきった後の定常状態では証明書を取れないが、参加者として加われば取れる**。
- discovery の最初の段階（SPDP）でも、subject 名は暗号化されずに出る（subject 名の出現回数が鍵なしの参加者でも 49 回あった）。

## 注意

- この結果は Fast DDS 2.14.6 のものである。実機などでバージョンが違う場合は、差分を再確認すること。
- 「ハンドシェイクで相手が証明書を送ってくる」のは、DDS-Security の既定プラグインの仕様上、認証が成立する前に双方が証明書を交換するためで、設定の不備ではない。
  証明書を隠したい場合は、ネットワーク側（隔離・VLAN）で守る必要がある。
